Fork #61 create/edit drawer model.

A fullSaveControls drawer now behaves differently by mode, keyed on isCreateDrawer (autosave needs a document id, which a create drawer lacks):

- CREATE drawer (no id): autosave OFF; renders explicit Save Draft + Publish buttons. Labels come from the consuming app via drawerContext.createLabels = { saveDraft, publish } (varig: "Save Draft & Close" / "Publish & Close"; #45's onSave already closes a create drawer after any save).
- EDIT drawer (id exists): autosave runs (gate now (!isInDrawer || fullSaveEditDrawer)) and the controls collapse to a lone Publish button, like the full-page editor; the drawer stays open after publish.

Also: SaveDraftButton gained an optional label prop (PublishButton already had one). A collection that registers a custom PublishButton reads createLabels from useOptionalDocumentDrawerContext itself (RenderCustomComponent cannot pass it a prop).

Supersedes v3.85.0.4 (broken autosave-in-create-drawer) and v3.85.0.5 (showSaveDraftButton flag, no create/edit split). v3.85.0.6 is the current release.
